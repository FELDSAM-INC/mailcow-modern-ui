# Community Preview 3

This preview fixes DNS diagnostics and simplifies the suggested SPF records.

## Changes since Preview 2

- Fix false DNS lookup failures when a DNS server answers the requested record but rejects an
  additional `ANY` query. Standard record lookups now request only the needed record type,
  allowing SPF include chains to be evaluated correctly. DNSSEC validation remains enabled.
- Suggest `mx` instead of adding explicit `ip4` and `ip6` addresses to SPF records. Existing
  includes, redirects, address ranges, and the final policy are preserved.
- Avoid duplicating existing MX authorization. When a record already includes it but SPF still
  fails, explain that the MX addresses and earlier SPF mechanisms need checking.
- Remove the separate IP authorization suggestions and clarify that the domain's MX records
  must point to the sending server. Updated help is available in English, Czech, and Slovak.

For example, `v=spf1 include:provider.example -all` now gets the suggestion
`v=spf1 mx include:provider.example -all`. DNS diagnostics do not change published DNS records.

## Install or update

Use **mailcow 2026-09a or newer**, including **2026-10**. The accepted database schema remains
`18082026_1200`; this preview adds no API database migrations or API contract changes.
Older releases remain untested; see the [compatibility notes](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.3/docs/compatibility.md).

- [Manual installation](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.3/docs/installation.md)

Fetch the release tags, check out `v0.1.0-preview.3`, and follow the update guide or rerun Ansible
with the same inventory. Preserve `modern-ui/secrets.env` and existing mailcow backups. Both
installers select the same pair of images pinned by digest. Manual activation preserves the
saved `/` or `/ng/` URL; Ansible applies the inventory's URL selection.

## Validation and known limitations

- 118 targeted API DNS tests passed, including a regression for a valid TXT answer followed by
  a failing `ANY` query. Formatting and static analysis passed.
- 342 UI DNS unit/component tests passed. Six SPF suggestion and clipboard browser checks passed
  across desktop Chromium, mobile Chromium, and mobile WebKit. Type checking, linting, translations,
  and the production build passed.
- The fixes were deployed and checked on the AMD64 development installation. The previously
  failing SPF include chain now evaluates without DNS lookup errors.
- All 34 installer tests, Ansible syntax and fixture checks, and nginx routing checks passed.
  The release verifier confirmed both public image tags, digests, architectures, and source revisions.
- The full UI end-to-end CI suite still reports failures; the targeted DNS browser checks above
  passed. This remains a community preview, without full browser acceptance sign-off.
- Release image publication requires source, dependency, configuration, and container checks.
  Both image architectures are scanned before version tags are published.
