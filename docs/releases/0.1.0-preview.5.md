# Community Preview 5

This security maintenance preview hardens account recovery, passkey ownership, and
connections that use stored credentials. It also updates API and UI dependencies,
requires patched runtime libraries, and improves container build caching.
It remains a community prerelease.

## Changes since Preview 4

- Refuse passkey sign-in, enrollment, and management when legacy administrator and mailbox
  accounts share a username. Those accounts must have distinct usernames to use passkeys safely.
- Extend the same ownership protection to second factors, including pending sign-in, suspended
  factors, and account rename/deletion. Prevent new mailbox/administrator name collisions.
  Existing ambiguous accounts require operator repair before their factors can be used or moved.
- Revoke outstanding reset tokens when a user or administrator changes or removes a recovery
  address. Recovery changes are serialized with reset issuance and completion.
- Require STARTTLS and a trusted certificate matching the configured next-hop hostname before SMTP
  connection tests send stored login credentials. Tests without credentials and TLSA
  certificate diagnostics retain their existing behavior.
- Keep the application encryption key out of app-password SQL queries; compute keyed version
  fingerprints in PHP.
- Recheck and lock current domain ownership for alias, alias-domain and BCC mutations, including
  later bulk items after a domain transfer or assignment revocation.
- Require SMTP password re-entry or explicit removal when a relayhost or transport changes
  its destination or username. Shared transports can still adopt credentials already bound to
  their target next hop.
- Require the identity-provider secret to be supplied again when the LDAP destination port,
  TLS mode, or certificate-verification policy changes. Equivalent effective LDAP ports retain
  the stored secret.
- Remove the dedicated companion-repository token from UI smoke CI, disable persisted checkout
  credentials, and restrict smoke runs to trusted main/release refs. Pull requests and manual
  runs on contributor branches cannot start that job.
- Bind sessions, impersonation targets, and API keys to the account instance, including legacy
  deletion and recreation within the same second. Lock the owner during API-key issuance and
  reject missing account bindings.
- Refuse delegated alias-domain creation when its sender-permission cleanup would affect another
  tenant; require the sender permission for cleanup within assigned domains.
- Bound the quarantine template renderer to 128 MiB before compilation and rendering, in addition
  to existing time and output limits. Oversized expansions return a validation error.
- Limit deletion-preview alias names to the caller's domains while preserving full cleanup counts.
- Preserve local mailbox suspensions during identity-provider sign-in: mapped templates cannot
  reactivate an inactive or login-disabled mailbox. An administrator must explicitly reactivate it.
  Preserve the distinct login-disabled status in model reads so it also ends existing sessions.
- Isolate the legacy Sieve parser with strict execution, memory, input, and output limits.
  Complex scripts that exceed those limits are refused; normal syntax messages and the
  upstream parser are preserved. Update the disposable runtime security fixtures for account binding.
- Bind browser cache and write-replay ownership to a non-authenticating session reference, so
  signing back into the same account in another tab clears previous-session state.
- Mark SSO and reset-password callback responses `no-store` in both URL layouts.
- Keep PR image jobs read-only; reserve registry writes for trusted main/release-tag jobs while
  sharing the native build steps and cache configuration.
- Apply a no-referrer policy in the HTML before resource loads, protecting reset and SSO
  query tokens even without the supported outer proxy policy. Restrict development mock
  redirects to approved UI origins and reject malformed request targets.
- Discard quarantine downloads whose response body finishes after an account switch, before
  creating a local file. Message and attachment downloads share the same session check.
- Limit quarantine MIME parsing to 256 total parts, including nested messages, before opening
  attachment streams. Skip attachment decoding without attachment permission. Excessively
  complex messages return a controlled refusal; permitted raw message downloads remain available.
- Keep attachment bytes out of quarantine text previews when attachment access is disabled,
  including raw MIME fallbacks, named text attachments and attached-message children.
- Require password re-entry when a sync job's remote host, port, encryption, or username changes,
  preventing the stored credential from being redirected to a different connection. The editor
  explains the requirement, and API v2 enforces it independently.
- Limit development mock request bodies to four MiB and reject oversized or chunked uploads
  before unbounded buffering. The mock server is not included in production images.
- Update Laravel to `13.42.0` and Symfony components to `8.1.11`, including their
  security fixes. Refresh compatible Composer dependencies while retaining PHPUnit 12
  and the OAuth test dependency compatible with mailcow's existing schema.
- Require `libexpat` `2.10.0-r0` or newer in both application images and `libxslt`
  `1.1.43-r4` or newer in the UI image. These explicit minimum versions invalidate
  previously cached layers containing older libraries.
- Update compatible frontend dependencies and the Node 24 build image. Repair optional
  peer entries in the npm lockfile so installation also works with supported Node 22/npm 10.
- Build AMD64 and ARM64 images on native runners, with separate caches for each platform.
  Reuse the frontend build and shared API development image across CI jobs. Image publication
  assembles the tested platform digests without building the images again.
- Update pinned CI actions across all three repositories. Source, dependency, configuration,
  and image security gates remain enabled; no vulnerability exceptions were added.

The API adds an automatic migration for its own account-identity table and API-key binding.
Upstream mailcow tables are unchanged. Existing valid API keys are migrated; browser sessions
require a new sign-in after upgrading. Password-change behavior is unchanged. Existing API
response fields are preserved; `/me` adds a non-authenticating browser `sessionId` reference.
Insecure connection tests, ambiguous factor operations, and
quarantine previews exceeding the MIME complexity limit now fail safely.

## Install or update

Use **mailcow 2026-09a or newer**, including **2026-10**. The accepted database schema remains
`18082026_1200`. Older releases remain untested; see the
[compatibility notes](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.5/docs/compatibility.md).

- [Manual installation](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.5/docs/installation.md)
- [Install or update with Ansible](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.5/docs/ansible.md)
- [Update an existing installation](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.5/docs/maintenance.md)
- [Screenshot tour](https://feldsam-inc.github.io/mailcow-modern-ui/)

Fetch the release tags, check out `v0.1.0-preview.5`, and follow the update guide or rerun Ansible
with the same inventory. Preserve `modern-ui/secrets.env` and existing mailcow backups. Both
installers select the same pair of images pinned by digest. Manual activation preserves the
saved `/` or `/ng/` URL; Ansible applies the inventory's URL selection.

## Validation and known limitations

Fresh full-repository Codex Security scans completed through ChatGPT authentication on both
exact component revisions. Findings were reviewed and confirmed issues were fixed before the
final scans. The final UI scan reported no findings; the API scan's one workflow finding was
assessed against the documented trusted repository-writer boundary and
[GitHub's secret-access model](https://docs.github.com/en/actions/reference/security/secure-use#use-secrets-for-sensitive-information). Detailed reports remain private. These source reviews are risk-focused, not exhaustive
line-by-line audits or verification of every deployment.

Required contract/build, static analysis, unit/feature tests, source/dependency/configuration/secret
checks, CodeQL and AMD64/ARM64 image checks passed for the component revisions above. Both
public version tags were verified for architecture coverage and source labels, and the installer
pins their immutable digests. Installer validation passed 34 tests.

- The full UI end-to-end suite has known failures carried over from earlier previews.
  Full browser acceptance sign-off remains outstanding.
- Internal service traffic, including reset-mail SMTP, relies on isolation of the trusted mailcow
  network. Untrusted workloads and remote connections over untrusted networks are unsupported.
- Sync-job permission delegates IMAP connections from the runner, including private servers.
  Operators must restrict permission grants and apply any required destination policy on the
  runner network; the API does not enforce public-address-only destinations.
- Automated security checks do not replace an independent audit. Independent security
  review remains pending before a release candidate.
