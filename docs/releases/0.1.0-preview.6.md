# Community Preview 6

This preview adds mailcow **2026-11** support while retaining compatibility with
**2026-09a and 2026-10**. It also completes the identity-provider setup form and
improves updates of older and customized installations. It remains a community prerelease.

## Changes since Preview 5

- Mailbox groups, shared mailboxes, membership and delegated permissions, with
  scoped controls for administrators and domain administrators.
- LDAP/AD and Keycloak synchronization settings, offboarding safeguards, previews,
  recent runs and identity links. Group and offboarding settings are available
  when creating a provider, and are saved atomically with its connection settings.
- Clear identity-provider sections for connection, login, mailbox templates,
  synchronization, offboarding and groups, shared between setup and later edits.
- Sync sources with provider presets and OAuth connections, private or scoped
  access, queue priorities, and global limits for parallel processes and bandwidth
  in KB/s per process. Existing REST v2 sync-job clients remain compatible.
- Separate administration of legacy API v1 keys, preserving the distinction from
  scoped REST v2 keys and protecting service-managed keys.
- Fail2Ban's unban-all action with confirmation, and consistent ACL handling on
  both supported database schemas.
- Upstream 2026-11 nginx routing, trusted client-IP handling and internal endpoints
  preserved in both `/` and `/ng/` layouts.
- Installer support for Python 3.6+ and updating existing custom or branded
  deployments without replacing their integration configuration.
- Contract compatibility checks retain named schema branches and merge `allOf`
  constraints, accepting optional additions while still detecting breaking changes.

New controls appear only when the server supports them. The addon does not update
mailcow itself or migrate upstream mailcow tables; run the normal mailcow update
separately. Existing sync-job custom options may need conversion to the new
allowlisted typed options; unconverted upstream options are ignored. See the
[2026-11 feature and migration notes](https://github.com/FELDSAM-INC/mailcow-rest-v2/blob/v0.1.0-preview.6/docs/mailcow-2026-11.md).

## Install or update

Use **mailcow 2026-09a or newer**, including **2026-10 and 2026-11**. The API accepts
schemas `18082026_1200` and `02112026_1600`. Older releases remain untested; see
[compatibility](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.6/docs/compatibility.md).

- [Manual installation](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.6/docs/installation.md)
- [Install or update with Ansible](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.6/docs/ansible.md)
- [Update an existing installation](https://github.com/FELDSAM-INC/mailcow-modern-ui/blob/v0.1.0-preview.6/docs/maintenance.md)
- [Screenshot tour](https://feldsam-inc.github.io/mailcow-modern-ui/)

Fetch tags, check out `v0.1.0-preview.6`, and rerun the installer with the same
configuration. Preserve `modern-ui/secrets.env` and existing mailcow backups.
Update **both** the API and UI images. Remove or update explicit image overrides
in your Ansible inventory; those override the release manifest's defaults.

The deployment helper supports Python 3.6+, but Ansible controllers must still
support the Python version installed on the target server.

## Validation and known limitations

Fresh full-repository Codex Security scans completed through ChatGPT authentication
on both exact component revisions. The API scan reported no findings. The UI scan's
conditional CI finding was assessed against the trusted repository-writer boundary
already documented for Preview 5 and [GitHub's repository-secret access model](https://docs.github.com/en/actions/reference/security/secure-use#use-secrets-for-sensitive-information).
Detailed reports and the assessment remain private. These source reviews prioritize
security-sensitive paths; they are not exhaustive line-by-line or deployment audits.

Required contract/build, static analysis, unit/feature tests, source/dependency/configuration/secret
checks and AMD64/ARM64 container checks passed for the component revisions above.
Installer validation passed 41 tests, 31 Python 3.6 compatibility tests, Ansible
syntax and integration checks, and nginx routing tests against both upstream schema
fixtures. The release pipeline verifies public version tags, immutable image digests,
both architectures and source revisions before publishing the installer release.

- The full UI end-to-end suite has known failures carried over from earlier previews.
  Full browser acceptance sign-off remains outstanding; focused tests cover the
  new identity-provider setup flow on desktop Chromium and mobile Chromium/WebKit.
- Independent security review remains pending before a release candidate.
- Internal service traffic relies on isolation of the trusted mailcow network.
- Sync jobs may connect to private IMAP servers; operators control permission
  grants and any destination restrictions on the runner network.
